# WakeUpHere 醒來確認紀錄

真正的城市當地早上 08:00 鬧鐘響起後，第一次按下搖桿確認鍵，同時代表「我知道了／我醒來了」。聲音照常停止，WakeUpHere 畫面、選址與操作介面維持原樣。

## 在 WakeUp Map 查看

使用 Pi 當時登入的帳號寫入紀錄，沒有固定為 YuPie。到 WakeUp Map 選擇該帳號，在地圖或紀錄列表開啟紀錄，可看到：

- 實際按下確認鍵的時間及 Pi 時區。
- 原先預約的城市與當地 08:00 的排程時間。
- 依按鈕時間套用 WakeUp Map 現行選址規則得到的醒來城市。
- 醒來城市與預約城市的球面直線距離（公里），以及確認延遲時間。

「醒來城市」是時間所對應的地圖城市，不是 GPS 實際所在地。若此瀏覽器已有 WakeUp Map 基地座標，沿用該設定；否則依既有無基地選址規則處理。此類紀錄不呼叫 AI、不產生早餐或等待早餐圖片。

WakeUp Map 在視窗重新取得焦點時及每 60 秒更新紀錄。Ctrl+H 模擬鬧鐘不新增醒來紀錄；部署前的按鈕操作無法回補。

## 寫入與重試

按下瞬間先保存時間、排程時間與帳號，放入瀏覽器既有持久化佇列。斷線後恢復連線會重試，保留原始按下時間，不使用稍後收到請求的時間。請勿在同步完成前清除瀏覽器資料。

每個帳號、預約城市、排程時間產生固定識別碼；一般重試會查詢並沿用同一筆紀錄。Notion 沒有唯一索引交易，多裝置同時提交同一事件仍可能存在競爭。

## 資料庫設定

預約狀態繼續使用 `WAKEUPHERE_PAGE_ID`；醒來紀錄寫入 WakeUp Map 的 `NOTION_DATABASE_ID`。同一 Notion integration 必須有兩個資料庫的讀寫與更新欄位權限。缺少主資料庫設定或寫入失敗時，事件留在佇列重試。

後端會新增 `wakeuphere_` 前綴的事件識別、帳號、按下時間、排程時間、Pi 時區、目標城市座標與時區、距離和延遲欄位；保留既有紀錄欄位與內容。部署不會建立假醒來資料，需下一次真正鬧鐘確認才會產生紀錄。
