# WakeUpHere 醒來確認紀錄

真正的城市當地早上 08:00 鬧鐘響起後，第一次按下搖桿確認鍵，同時代表「我知道了／我醒來了」。聲音照常停止，WakeUpHere 畫面、選址與操作介面維持原樣。

## 在 WakeUp Map 查看

使用 Pi 當時登入的帳號寫入紀錄，沒有固定為 YuPie。到 WakeUp Map 選擇該帳號，在地圖或紀錄列表開啟紀錄，可看到：

- 實際按下確認鍵的時間及 Pi 時區。
- 原先預約的城市與當地 08:00 的排程時間。
- 依按鈕時間套用 WakeUp Map 現行選址規則得到的醒來城市。
- 醒來城市與預約城市的球面直線距離（公里），以及確認延遲時間。

「醒來城市」是時間所對應的地圖城市，不是 GPS 實際所在地。若此瀏覽器已有 WakeUp Map 基地座標，沿用該設定；否則依既有無基地選址規則處理。按鈕確認先立即保存紀錄，不等待 AI。收到雲端寫入成功的醒來紀錄 ID 後，WakeUpHere 會立即啟動獨立的背景工作，自動補上當地語言早安、雙語介紹、早餐圖片與食譜，寫回同一筆紀錄；不需要打開 WakeUp Map，也不重選城市或改動按鈕時間。

WakeUp Map 在視窗重新取得焦點時及每 60 秒更新紀錄。Ctrl+H 模擬鬧鐘不新增醒來紀錄；部署前的按鈕操作無法回補。

## 寫入與重試

按下瞬間先保存時間、排程時間與帳號，放入瀏覽器既有持久化佇列。斷線後恢復連線會重試，保留原始按下時間，不使用稍後收到請求的時間。請勿在同步完成前清除瀏覽器資料。

每個帳號、預約城市、排程時間產生固定識別碼；一般重試會查詢並沿用同一筆紀錄。Notion 沒有唯一索引交易，多裝置同時提交同一事件仍可能存在競爭。

## 資料庫設定

預約狀態繼續使用 `WAKEUPHERE_PAGE_ID`；醒來紀錄寫入 WakeUp Map 的 `NOTION_DATABASE_ID`。同一 Notion integration 必須有兩個資料庫的讀寫與更新欄位權限。缺少主資料庫設定或寫入失敗時，事件留在佇列重試。

後端會新增 `wakeuphere_` 前綴的事件識別、帳號、按下時間、排程時間、Pi 時區、目標城市座標與時區、距離和延遲欄位；保留既有紀錄欄位與內容。部署不會建立假醒來資料，需下一次真正鬧鐘確認才會產生紀錄。

## 預約與實際位置比較

地球圖篩選與 Review Journal 預約欄位，詳見 [預約與實際甦醒地圖](wakeuphere-reservation-map.md)。

## 地方內容與早餐恢復

真正鬧鐘的搖桿確認鍵會自動排入內容工作，文字準備好後再產生早餐圖片。準備中的圖片沿用原本的早餐佔位狀態；失敗會顯示「重新準備內容」按鈕。WakeUpHere 將待辦頁面 ID 存在 `wakeuphere.contentOutbox`，每 15 秒、重新連線及頁面重開時自動重試；接續 Notion 上已保存的圖片工作，已完成內容不重複生成。內容工作獨立於預約佇列，失敗不會卡住取消、換城市或其他日期的工作。請保持 Pi 的 WakeUpHere 開啟；關機期間不會發起新的生成請求，重開後會接續。

WakeUp Map 開啟黑點時會先等背景工作，準備好後自動更新；停留約三分鐘仍缺內容時才啟動備援補齊，明確點擊重試則立即執行。Ctrl+H 模擬不產生正式紀錄，也不啟動內容生成。

`POST /api/wake-up-now` 的 `action: complete-awakening` 只更新指定主資料庫內的既有醒來紀錄；`/api/wake-up-image` 對這類紀錄使用其已保存的城市與早餐工作，不接受客戶端換城市。增加的 `wakeuphere_content_status` 與 `wakeuphere_image_job` 欄位只記錄內容準備狀態。

## 圖片模型

正式環境驗證發現舊 `gpt-image-1` 已停用（[官方停用資訊](https://developers.openai.com/api/docs/guides/tools-image-generation)）。圖片生成預設改用 `gpt-image-2.5-flare`，可透過 `OPENAI_IMAGE_MODEL` 指定仍受支援的模型。正式 API 和本機服務使用相同預設；已儲存的早餐圖片與原始醒來紀錄不受影響。

## 早餐圖片每筆只生成一次

同一筆 Notion 甦醒紀錄的圖片會儲存在 Cloudflare R2，Notion 保存其網址。一般 Wake Up Now 與 WakeUpHere 使用同一個圖片 API。只要已有圖片網址，就沿用原圖；食譜缺漏可補文字，不重生圖片。不同日期／不同紀錄仍各自擁有自己的圖片。

新圖片使用以紀錄 ID 衍生的固定物件路徑，避免同城市同時間的不同帳號互相覆寫。R2 工作收據與條件式寫入防止兩個伺服器同時產圖；PNG 存好後才寫回 Notion。Notion 寫回失敗時，重試從 R2 修復，不重新呼叫圖片模型。既有舊路徑圖片維持原網址，不強制搬移或重生。

圖片生成請求結果不明（例如送出後網路中斷）時，系統保留已送出的標記，不自動要求第二張。若原圖尚未成功存入 R2，需先查明原次結果再人工處理；不能為了補圖而默默再次生成。確認未成功的 API 錯誤才允許重新嘗試。請勿手動刪除已保存的原圖或工作收據。

R2 的條件式寫入保證由 [Cloudflare 官方文件](https://developers.cloudflare.com/r2/reference/consistency/) 說明。
