# Store and reuse each record's breakfast image

User requires one generated image per wake record, persisted and never regenerated by refresh, retry or competing Pi/map requests. Scope is each Notion wake record, not one shared image per city.

All public image requests first read the authoritative Notion page, including ordinary Wake Up Now jobs. A saved Image URL always wins, independently of recipe completeness. Missing text can be repaired without generating a new image. Unify the local HTTP image route with the deployed implementation.

For new images use a deterministic per-record R2 image key plus a persistent job receipt. R2 conditional PutObject (If-None-Match/If-Match) is the cross-instance ownership mechanism. Persist recipe/prompt and image_requested before calling the image provider. Store image bytes before Notion writeback; a failed Notion update must recover the stored bytes/receipt, never call the image model again. Never overwrite an existing PNG. A timed-out/network-unknown image result does not automatically release the image_requested marker: billing safety takes priority over silently requesting a second image. Only confirmed unsuccessful provider responses may be retried. Before-image stale preparation can be reclaimed after the function's maximum lifetime.

Tests first: existing ordinary image, incomplete recipe with existing image, competing requests, retry after Notion failure, no regeneration after ambiguous image result, provider failure retry, persistent image reuse with changed client payload. Exercise real production cached record read-only, without new image calls. Run existing content/booking/map suites, emitted JS smoke tests, lint/build; deploy GitHub/Vercel and safely sync workspace.

Cloudflare atomic conditional operations: https://developers.cloudflare.com/r2/api/s3/conditional-operations/ and https://developers.cloudflare.com/r2/reference/consistency/ . Notion alone does not provide an atomic unique claim.
