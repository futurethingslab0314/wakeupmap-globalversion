# 預約與實際甦醒地圖

WakeUp Map 新增三種位置篩選：全部、預約位置、實際位置；以和語言切換相同尺寸的控制項排列於同一列，不顯示額外灰色說明。原本的「我的甦醒地圖」與「今天誰醒來」仍分別控制個人及今日共同觀看範圍。WakeUpHere 本身的介面、搖桿與鬧鐘流程不變。

## 地球圖

- 橘色空心點：今天有效的預約甦醒位置。今天依各預約城市的 IANA 時區判定，鬧鐘時間為該城市當地 08:00。
- 黑色實心點：已有的實際甦醒紀錄，保留歷史。WakeUpHere 的正式確認事件使用按鈕當下依時間選出的城市，不是 GPS。
- 「全部」中，今日完成確認的預約與實際位置以橘色虛線連結，標註公里距離。「預約位置」或「實際位置」單獨觀看時不顯示配對連線。
- 兩個位置完全相同時，黑點與橘圈同心顯示，距離仍為 0.0 km。
- 點擊預約位置可查看帳號、預約城市、當地日期、08:00 排程與狀態；完成後也可查看配對的實際城市、按鈕時間和距離。

預約在 08:00 後才建立，會依原有鬧鐘規則排到隔天，不冒充今天的預約。跨日後有效的持續預約會顯示於新的一天。取消或換城市會移除舊的未完成預約；已確認事件仍以其原始排程時間與目標城市快照呈現，不會被後來的換城市覆蓋。

## Review Journal

表格列出日期（預約城市當地日期）、預約甦醒位置、實際甦醒位置、距離、狀態／問候與查看細節。

今天尚未確認的有效預約列為「待甦醒」，實際位置與距離不虛構。收到正式確認後，該筆改為一列含兩個城市、按鈕時間與距離的完成紀錄，不另留重複的待甦醒列。已完成事件的原預約位置會保留在歷史列。原有早餐紀錄保留，沒有預約的列以「—」顯示。

目前預約資料庫只保留每個帳號最新狀態，因此無法重建過去未確認、已取消或已換城市的預約歷史；也不會替部署前的紀錄補造預約位置。

## 更新與 API

新增唯讀 `GET /api/wakeuphere?view=map`：沿用原先最新有效預約的去重規則，回傳 canonical 城市座標、IANA 時區、預約更新時間及今日 08:00 排程。這個 GET 不會寫入 Notion，也不新增 serverless function。原本 Pi 名單的 GET 回應不變。

每 60 秒及視窗重新取得焦點時更新。預約讀取與主紀錄讀取互相獨立；暫時失敗時保留上一份預約資料並顯示重試提示。日誌不隨地球圖位置篩選隱藏歷史列。

## 驗證

`npm run test:reservation-map` 驗證時區日期、夏令時間、取消／換城市、配對去重、帳號範圍、零距離與 Journal 呈現。

`npm run test:serverless` 直接載入編譯後 JavaScript，並用 Notion fixture 測試地圖 API 讀取打包的城市資料，避免僅在 TypeScript 開發載入器下正常。
