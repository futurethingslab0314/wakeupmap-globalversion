# WakeUpHere 自動更新

更新日期：2026-11-16。

> 已加入 [每日八點鬧鐘持久化](wakeuphere-daily-alarm.md)：現行版本除了下面的更新暫存，也會在重新整理／重開機後還原已確認城市與排程。響鈴中仍延後網站更新；無互動音效需另確認 Pi 啟動參數。

## 裝置行為

網站啟動後及每 60 秒檢查一次 `/wakeuphere/version.json`，網路恢復時也會檢查。
偵測到不同部署版本後，使用含版本參數的 URL 重新載入，避免沿用舊 HTML 快取。
相同版本、無效回應或網路錯誤不會重整。響鈴中或重新選址確認視窗開啟時，延至後續檢查。

使用者名稱仍保存在原本的 localStorage。更新前若已完成城市選擇（Stage 3），
會在同分頁 sessionStorage 暫存名稱、洲、國家、城市，載入新版本後嘗試還原。
還原會重新執行預約畫面的一般 Notion 同步流程；不恢復響鈴模擬時鐘或音訊播放狀態。
尚未完成的選址流程、儲存空間不可用或新版找不到原城市時，會回到選洲畫面。
重新開機或手動重新整理不會額外儲存城市；這裡只處理自動部署更新。

## 第一次啟用

已經開著的舊網站尚無版本檢查程式。部署本功能後，每台 Pi 必須先重新整理一次，
或重新開機。此後不需修改 Pi 啟動服務，即可偵測後續部署。
重整會重建瀏覽器音訊環境，音效可能需要下一次搖桿或點擊互動才能播放。

## 建置與驗證

`npm run build` 執行 Vite，再執行 `scripts/stamp-wakeuphere-version.mjs`：

- 每次建置產生新的 UUID，寫入建置後 HTML meta 與 `version.json`。
- 更新檢查程式的載入 URL 也帶同一版本。
- public 原始檔仍保留 marker；直接開發模式不啟動部署更新。

請使用完整的 `npm run build`，不要只執行 `vite build`。
測試：`npm run test:wakeuphere-update`。
只在需要的版本資訊請求上停用快取，不變更 OpenStreetMap 圖磚快取。
